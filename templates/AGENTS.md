# SpecFirst repository rules

<!-- 复制到项目仓库根目录；这是给 AI 的仓库级纪律，简短 > 全面。 -->

1. 先读 `spec/CONVENTIONS.md`，再读自己角色和当前任务相关的 Spec（按 `spec-map.yml`）。
2. API、数据、设计和测试以各自目录里的原生契约为准；产品行为以 `REQ-*` 和 `ACCEPTANCE.md` 为准。
3. 发现需求缺口、文档冲突或公共契约变化时，先更新 Spec 并走 PR 评审，不要绕过。
4. 修改公共契约、数据迁移或不可逆操作前，先向人确认范围。
5. 完成后报告：使用的 Spec ID、修改的文件、发现的偏差、真实跑过的验证命令（附结果）。
