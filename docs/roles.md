# 角色阅读边界

> 给谁看：所有角色。一句话原则：**每个角色只读自己负责的事实，加上当前任务需要的上游约束；默认清单不是白名单，是起点。**

| 角色 | 默认阅读 | 主要产出 |
|---|---|---|
| PM | `project/`（目标、里程碑、风险）、需求摘要 | 项目状态（Markdown 表格）、风险与计划 |
| Product | `project/`、相关需求、验收标准 | `REQ-*` 与 `ACCEPTANCE.md` |
| Design | 相关 `REQ-*`、`ARCH-*` 的边界部分 | `DES-*` 与设计资源 |
| Architect | `REQ-*`、现状代码边界、受影响 API/Domain | `ARCH-*` 与 ADR |
| Frontend | `REQ-*`、`DES-*`、相关 API、测试 | UI 实现与前端验证 |
| Backend | `REQ-*`、`ARCH-*`、相关 API/Domain、测试 | 服务实现、迁移与契约实现 |
| QA | `REQ-*`、`ACCEPTANCE.md`、相关 API/Design | `TEST-*`、自动化测试和报告 |
| AI Agent | 当前角色入口 + 任务映射的 Spec | 草案、代码、测试和执行报告 |

几条使用规则：

1. **PM 的状态就是表格**。目标、里程碑、风险用 Markdown 表格维护，评审会上直接改、直接截进周报，不经过任何工具或 YAML。
2. **任务引用谁就补读谁**。比如前端任务动了 API 的错误码，就补读 `API-*` 的错误约定；其余不要求通读。
3. **一个人多角色时合并清单**，比如小团队的前端同时是 Design 负责人。
4. **AI 按角色领清单**。给 Agent 的入口在 [Agent 指南](agent.md)，`spec-map.yml` 里可以给每个角色配默认清单。

角色边界的目标不是互相隔离，而是让每个人（和 AI）读到的都是**和自己决策有关的最小集合**——文档再多，读到脑子的只有该读的几页。
